**Codex review redesign summary (codex Cluster 1, 2, 3, 6, 7, 8, 10):**

- **Cluster 1 — audio-thread RT-safety envelope:** the `WaitableEvent::signal()` from the audio thread is REPLACED with an atomic sequence counter the decoder thread polls (short timed wait). The decoder thread's polling cadence is ~10-25 ms (well under the ~167 ms swap interval), so there is no perceptible latency increase, and the audio-thread cost drops to a single relaxed atomic increment (no OS sync primitives).
- **Cluster 2 — owned-payload queue:** the previous `SpscRing<VideoRecvBufferView, 4>` (raw pointer into a single shared decoder-owned `slotCopyBuf_`) is REPLACED with **Option A (codex-preferred)**: `VideoRecvState` owns `std::array<VideoRecvSlotSnapshot, 4> decoderSlots` (4 pre-allocated 4 MB buffers) plus `SpscRing<int, 4> decoderSlotIndexQ` carrying integer indices. Audio thread memcpys bytes + offsets into `decoderSlots[next_fill_index]` then pushes the index. Decoder reads `decoderSlots[popped_index]` — ownership unambiguous, no back-to-back overwrite hazard, frameOffsets fully copied (not raw-pointing into receive-state).
- **Cluster 3 — lifetime triangle:** `Openh264Decoder` now has a public `setSink(jamwide::PeerVideoSink* sink)` API that is SAFE to call with `nullptr`. After `setSink(nullptr)` returns, the decoder thread will not dereference `sink_` further (guaranteed by holding `sink_lock_` during both the setter and `scaleAndSwapImage_`'s sink touch). Plan 21-03's shutdown protocol relies on this.
- **Cluster 6 — wire-format contract:** Plan 21-01 Task 1 pinned the wire-format contract in a comment on `struct VideoRecvBuffer`. Plan 21-02's parser EMBEDS the same contract in `parseSlotAndFeed_` comments AND adds a unit test asserting the marker payload size (20 bytes after outer prefix consumed; outer prefix value MUST equal 20).
- **Cluster 7 — full-slot bytes test:** a new sub-test `test_pushSlotView_full_ninjamzap_bytes` exercises the audio→decoder live path (not pushNalChunk) with full NinjamZap-shape slot bytes. Uses the new `marker_payload_outer20.bin` fixture for byte-exact regression coverage of the Phase 20 commit 6d23b5c lesson.
- **Cluster 8 — pollOneFrameForTest race:** the test result is held in a `TestFrameResult` struct (owned by Openh264Decoder, protected by `result_lock_`) instead of a raw `juce::Image*` written by the decoder thread. No UAF on test timeout.
- **Cluster 10 LOW — `std::atomic<std::thread::id>`:** replaced with mutex-protected `std::thread::id` value under JAMWIDE_BUILD_TESTS (lock-free not guaranteed on all standard libraries).

Purpose: COD-03 ("Remote video bytes decode per-peer to a `juce::Image`, with one independent decoder instance per remote user") — one decoder thread per peer, isolated, software libavcodec backend, drop-frame-and-recover-on-next-IDR error semantics. Per `feedback_proven_over_pure` the decoder is the ONLY green-field piece of Phase 21 (NinjamZap upstream has no decoder reference). Apply Phase 19 HIGH-4 AsyncUpdater pattern + Phase 20 R4 H9 7-step destructor template verbatim.
