```cpp
static inline bool is_video_fourcc(unsigned int fcc)

    const unsigned char b0 =  fcc        & 0xff;  // 'H', 'V', 'M'
    const unsigned char b1 = (fcc >>  8) & 0xff;  // '2', 'P', 'J'
```

```bash
       | grep -E 'libx264|x264_encoder|x264_init' > /dev/null; then

    *macos-*)

           | grep -vE '@rpath|^/usr/lib|^/System|^/Users.*lib' > /dev/null; then
        echo "FAIL: $PLAT_DIR has unexpected dynamic deps" >&2
        otool -L "$PLAT_DIR/lib"/*.dylib | grep -vE '@rpath|^/usr/lib|^/System|^/Users.*lib'
        exit 1
      fi ;;
  esac
  echo "OK: $PLAT_DIR"
done
```

## Shared Patterns

### Pattern A: SPSC queue + drop-counter + accessor (apply to plan 14.3-02)

**Source files:** `src/core/njclient.h:837-842` (declarations), `:657-659` (accessor), `:3811-3814` (drop-bump on drain when disconnected), `src/core/njclient.cpp:2208` (drop-bump on producer try_push failure).

**Apply to:** `m_rawdata_sendq` + `m_rawdata_sendq_overflows` + `GetRawDataSendQueueOverflowCount()`. Memory budget: capacity 64 × `sizeof(RawDataItem)` (≈ 48 B) + the heap-buf payloads themselves (1 KB IDR frames typical, possibly MB for keyframes — owned-by-pointer, not inline). 64-deep ring header ≈ 3 KB; payloads pay-as-you-go. ### Pattern B: Verbatim port from NinjamZap with JamWide adaptation (apply to plans 14.3-02 and 14.3-03)

**Source files:** `ninjamzap-core/njclient.{h,cpp}` reference impls cited above.

**Adaptation rules:**
- Replace `WDL_Mutex m_rawdata_sendq_cs` + `WDL_PtrList<RawDataQueueItem> m_rawdata_sendq` → `SpscRing<RawDataItem, 64> m_rawdata_sendq` + `atomic<uint64_t> m_rawdata_sendq_overflows`.

### Pattern C: `if (!m_netcon)` Disconnect-safety guard (apply to plan 14.3-02 drain)

**Source:** `src/core/njclient.cpp:3806-3815` (`drainBroadcastBlocks` head). Drain-and-discard pattern: when `m_netcon` is null, the drain MUST still consume queued items (with overflow-bump for observability) so the producer thread doesn't fill the ring forever and so heap-buf payloads don't leak.

```cpp
if (!m_netcon)
{
  m_rawdata_sendq.drain([this](RawDataItem&& item) {
    delete item.payload;  // owned-heap-buf cleanup
    m_rawdata_sendq_overflows.fetch_add(1, std::memory_order_relaxed);
  });
  return;
}
```

Landmine L3 — without this guard, `NJClient::Run` will fire ONE TICK after Disconnect nulls `m_netcon`, deref it, and crash the DAW.
