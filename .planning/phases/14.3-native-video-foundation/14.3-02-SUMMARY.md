# Phase 14.3, Plan 02: RawData Send-Side Public API + SPSC + Drain + is_video_fourcc Summary

**Codec-agnostic transport scaffolding (send-half): NJClient::RawDataSendBegin/Write
public API callable from any thread + SPSC-bounded send queue with Codex M-8
overflow counter + run-thread drain block with Pattern C discard-on-Disconnect
guard + MAX_ENC_BLOCKSIZE chunking + RawDataCallback API for 14.3-03 + file-static
is_video_fourcc helper for H264 / VP8 trailing-space / MJPG.**

## Accomplishments

- Send-side public API matches NinjamZap upstream verbatim (RawDataSendBegin /
  RawDataSendWrite / RawDataCallback) with the API-consistency tax preserved —
  grep-discoverability against `ninjamzap-core` holds
- Bounded SPSC (capacity 64) replaces NinjamZap's unbounded `WDL_PtrList<RawDataQueueItem>`
  + `WDL_Mutex` (Phase 15.1 invariant — locked SPSC + observability counter)
- Pattern C discard-on-null-netcon guard inside `NJClient::Run`'s drain block
  prevents heap-buf payload leaks during Disconnect tear-down (Landmine L3 closed
  by construction; counter increment per discarded item is observable through
  `GetRawDataSendQueueOverflowCount()`)

  MJPG with the byte-order convention matching `MAKE_NJ_FOURCC` at njclient.cpp:212
  (Landmine L1 byte-order discipline preserved)
- Test-only public wrappers (`IsVideoFourcc`, `DrainRawDataSendQueueForTest`,
  `ChunkRawDataItem`) gated under `#ifdef JAMWIDE_BUILD_TESTS` allow direct
  in-process unit testing without a Net_Connection mock — 8/8 sub-tests GREEN

  per `git diff` — SC-7 indirect (no regression)
- VDO.Ninja stack byte-identical (`git diff -- juce/video companion | wc -l == 0`)
  — SC-7 explicit
- `m_rawdata_downloads` private member + `RawDataDownloadTracker` POD struct
  declared (empty list); 14.3-03 will populate from the receive-dispatch INSERT

## Deviations from Plan

None — plan executed exactly as written, with the following minor structural choices documented inline:

- **NJClient heap-alloc in tests:** the plan didn't anticipate the 8.72 MB
  size of NJClient; stack allocation crashes immediately on macOS. Switched
  to `std::unique_ptr<NJClient>(new NJClient)` inside each test function;
  documented inline. This is structural, not behavioral — the test surface
  is unchanged.

- **JAMWIDE_BUILD_TESTS=1 also on test_rawdata_send target:** the plan
  prescribed the gated wrappers but did not explicitly call out that the
  test's translation unit also needed the macro. Added
  `target_compile_definitions(test_rawdata_send PRIVATE JAMWIDE_BUILD_TESTS=1)`
  to the CMakeLists block; the njclient target already gets the def at
  line 137. Without this, the test source would not see the
  IsVideoFourcc / DrainRawDataSendQueueForTest declarations in
  njclient.h and would fail to link.

- **deferred-items.md created:** discovered 2 pre-existing test failures
  during the full-suite ctest sweep (test_encryption: undeclared
  `encrypt_payload_with_iv` introduced by commit 205c831 Windows BCrypt
  migration; test_flac_codec: roundtrip decodes 0 samples, last touched
  by 15.1-08 commit 9b9ce95). Logged in the new
  `.planning/phases/14.3-native-video-foundation/deferred-items.md`
  per the scope boundary rule — they are NOT introduced by 14.3-02 and
  are out-of-scope for fixing.
