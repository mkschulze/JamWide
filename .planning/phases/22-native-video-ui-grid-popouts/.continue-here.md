<decisions_made>

- **30fps frame pacing instead of 15fps** — Mark-Ninjamzap broadcasts at ~30fps (`frameCount=228` per interval); 15fps pacing fell behind, slot ring filled, snapshots dropped. 30fps keeps 1:1 for higher-fps peers and lower-fps peers just decode faster and wait.
- **640x480 receive surface instead of 320x240** — peers send 640x480+; downscaling to 320x240 then upscaling at tile caused double-scaling blur. Memory cost ×4 (~2.4 MB per peer sink), well within budget.
- **Javier Fix #2 option (a) instead of option (b)** — option (a) is `allow_skip_frames=0`, simpler and ships now. Option (b) (keep allow_skip_frames=1 but force IDR on detected skip) is more work and deferred. Trade-off: openh264 emits a warning that bitrate isn't controlled with skip=0; in practice 300 kbps budget at 640x480 @ 15fps baseline has plenty of headroom.
- **stripAtSuffix bypass before findSink** — wire usernames carry `@<peer-ip>` suffix (e.g. `Mark-Ninjamzap@172.16.30.x`); Phase 21 keys sinks by raw wire name. The strip must happen only at display, not at lookup.
- **Defer Phase 21 multi-broadcaster matching fix** — m_remoteuser_mirror needs a username field for per-peer audio-guid matching. Current code breaks on first active slot. Fix requires extending the mirror schema; deferred to Phase 21 followup #9.

</decisions_made>
