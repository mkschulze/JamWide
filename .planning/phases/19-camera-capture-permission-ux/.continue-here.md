## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| macOS Sonoma TCC revoke is deferred-to-restart | When toggling camera permission OFF for a running app, macOS shows a "Quit & Reopen / Later" modal and defers enforcement until next launch — frames keep flowing. Any UAT scenario that assumes a System Settings toggle stops frames mid-session is wrong. | advisory | When designing camera-revoke tests, use USB unplug or scripted AVCaptureSession invalidation. The Phase 19 FrameStallWatchdog is fine — it's the integration test trigger that needs correcting. |
| scripts/build.sh default target includes failing test_encryption | `./scripts/build.sh` with no args enumerates all targets including the pre-existing test_encryption compile failure (encrypt_payload_with_iv undeclared identifier). JUCE plugin targets may not even start linking. | advisory | Always pass explicit JUCE plugin targets: `./scripts/build.sh JamWideJuce_Standalone JamWideJuce_AU JamWideJuce_VST3 JamWideJuce_CLAP`. ninja's per-target graph correctly skips test_encryption since it's not a dep. |
| Cell 5 UAT spec is documentation gap, not code gap | FrameStallWatchdog at `juce/video/native/JamWideCameraDevice.cpp:83-99` is correctly implemented and unit-tested via `tests/test_camera_frame_stall.cpp`. Only the integration UAT Cell 5 description is wrong (assumes mid-session OS revoke). | advisory | When rewriting Cell 5, validate against the unit test's trigger model, not the System Settings toggle assumption. |
