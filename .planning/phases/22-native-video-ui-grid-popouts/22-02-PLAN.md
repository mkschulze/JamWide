<objective>
Build the in-main-view grid band container that hosts the tile substrate from Plan 22-01, wire the new ConnectionBar "Grid" button as the toggle entry point, and integrate the band into `JamWideJuceEditor::resized()` between `sessionInfoStrip` and `channelStripArea`. Purpose: This is the container + chrome integration layer. It owns the lifecycle of per-peer tiles via the 30Hz sink-poll Timer (D-13 Option a — recommended over distributor event surface to avoid touching Phase 21's now-closed code), and it owns the self-tile gating via `connectionBar.getCameraIsBroadcasting()` (D-07 — symmetric with peer-tile rule). Toggling is a pure UI operation (`setVisible` + `resized()`) — DISP-04's "no disconnect" requirement is satisfied by NOT touching `NJClient` at all in this plan.

**Codex review closures applied:**
- **H1 (BotFilter extraction):** Task 0 — extracting `isBot`/`stripAtSuffix` from `ChannelStripArea.cpp`'s anonymous namespace (where they have internal linkage and cannot be referenced from another TU) into a proper `juce/ui/BotFilter.h`/`.cpp` pair with external linkage in `namespace jamwide`. This becomes a Wave-0 prerequisite that must complete BEFORE Tasks 1-3 since VideoGridBand and the editor both depend on the header.
- **H2 (juce::HashMap — NARROWED in iter-2):** Original codex H2 ("`std::unordered_map<juce::String, ...>` may not compile") was over-broad. `juce/midi/MidiMapper.h:105` already proves `std::unordered_map<juce::String, int>` compiles in this codebase (JUCE 8 ships `std::hash<juce::String>`). H2 is **narrowed to the case where the value type is COPYABLE AND iteration determinism matters for serialized output** (Plan 22-04's `popoutBoundsMap` keyed `juce::Rectangle<int>`). For THIS plan's in-memory `std::unique_ptr<T>` storage (`peerTiles_`), revert to `std::unordered_map<juce::String, std::unique_ptr<RemotePeerTile>>`: `juce::HashMap` has NO `.find()` returning iterator AND `juce::HashMap::set()` does copy-assignment (`getReference(newKey) = newValue;` at `libs/juce/modules/juce_core/containers/juce_HashMap.h:244`), which fails template instantiation on move-only `std::unique_ptr`.
- **M4 (UAF risk):** Auto-open latch uses lock-release-then-sync instead of `MessageManager::callAsync([this]{...})` — the timer is already on the message thread, so the async shim was both unnecessary AND introduced a UAF surface (editor could be destroyed before the callback runs). Lock is released BEFORE the synchronous `toggleGridBand(true)` call.
- **M5 (typed callback):** VideoGridBand's `onPeerPopoutRequested` callback signature changes from `std::function<void(const juce::String&)>` to `std::function<void(jamwide::VideoPopoutTarget)>` per Plan 22-01's typed-callback refactor. NO `kSelfTileSentinel` constant exists; the tile classes already emit typed targets.
- **M7 (detached-grid sync):** VideoGridBand gains an explicit `Mode` enum (`MainBand` | `DetachedBand`) so Plan 22-03's `DetachedGridWindow` can construct its inner band with `Mode::DetachedBand` — the inner band suppresses its own `↗` detach affordance and the editor drives popout state on BOTH bands.
